# June v0.5.1 — local conversation repair

This release changes the application, not Qwen’s weights. Keep Qwen2.5 1.5B, Whisper base.en and the saved female voice. It does not promise perfect factual answers.

## Install and run

From the June folder, use the existing private Python/model setup, then:

```sh
npm run speech:setup
npm run audio:setup
npm run build
npm run model:start
```

Leave the model terminal running. In another terminal, run `npm start`, then open http://127.0.0.1:3001/. Stop with Control-C. `npm run speech:worker:setup` rebuilds only the resident worker after Whisper is installed. Apple command-line compiler tools are required. Helpers and models stay under `~/Library/Application Support/June/`, outside Git. `JUNE_SPEECH_HOME`, `JUNE_AUDIO_HOME` and `JUNE_DATA_HOME` are optional private overrides in ignored `.env.local`.

The app warms Nicky silently, the decoder, detectors and Qwen before hands-free becomes ready. This does not open a microphone. The model receives one discarded startup warm-up token, never a saved chat. While explicitly enabled hands-free is active, an empty load request renews residency without producing an answer. Downloads need internet; inference and audio remain local.

## Audio ownership

Select **Native Mac audio**, then **Enable hands-free**. Grant the separate macOS **June Audio** microphone request yourself. Preview needs output only. If permission is denied, allow June Audio under System Settings → Privacy & Security → Microphone, then retry. Browser microphone permission does not grant native permission.

Nicky audio buffers and microphone capture use one AVAudioEngine with Apple voice processing. Voice-processing input/output client formats are explicitly matched before startup; this fixes the reproduced `-10875` initialization failure on this Mac. The seven-channel aggregate uses explicit channel-zero mapping before mono conversion: the reproduced implicit mapping delivered silence despite nonzero input. An opt-in native diagnostic reports levels only, never audio. The processed input is continuously resampled to mono 16 kHz PCM and sent through bounded private pipes to Python. One second of room calibration precedes readiness. Sustained speech, gated by VAD and measured energy above the room floor, interrupts output; native mode does not repeatedly run Whisper to check interruption probes. Pre-roll retains the beginning of your words. Lexical wake results can use recent sustained speech evidence when Vosk finalises during a pause; they do not require speech in the exact result packet. Device changes, helper failure, missed heartbeats, Stop, hidden tabs and navigation stop owned audio; deliberate enablement is required again.

Browser audio is an explicit **manual-recording fallback**. It is not represented as equivalent speaker interruption. It never runs a second browser microphone alongside native capture. No recording is saved or sent to a commercial service.

## Decoder and latency

Pinned whisper.cpp v1.9.5 loads base.en once in a supervised worker. Jobs have IDs, at most one active job, bounded headers/audio/results, a 120-second deadline and an abort callback. Unresponsive cancellation causes a worker restart. The tested four-thread greedy candidate is **withheld**: it preserved the GPU identifiers but failed the exact-name gate, as did the baseline. The resident worker therefore retains the established two-thread beam-five decoder and temperature fallback. Model residency still removes repeated loading. Weak-confidence output asks for repetition instead of guessing; confident misspellings remain possible, so names require transcript review/correction.

New hands-free sessions default to Short (0.8 seconds). Normal and Patient remain available. Speech buffers complete sentences, with a safe clause boundary after at least eight words; the next segment may prepare while the previous one plays. Names, identifiers, abbreviations and fenced code receive conservative handling. No filler is inserted to imitate speed.

Timing labels distinguish observed end-of-turn silence, transcription, model first text, first playback event and playback completion. Browser lifecycle timing is an observation at the client, not a laboratory measurement of acoustic onset. Human finish-to-audible-answer and interruption timings require the room test. Diagnostics contain timings/ownership only, without spoken content or personal facts.

## Facts and output

Explicit questions about your approved name, colour, age, location or saved details use approved facts directly, including questions with fillers and multiple clauses. Current relevant user corrections can take priority without silently changing saved memory. Unrelated questions receive no personal facts. Sources are the actual approved facts. Memory edits, deletion and source chats retain their existing separate controls.

A central capability description prevents claims of connected calendars, browsing, payments or purchases that June cannot perform. Ordinary explanation and drafting remain available. Repeated-output loops end generation and queued speech, label the reply and offer manual retry; displayed text remains. The **Approved facts provided** disclosure describes supplied context, not proof that Qwen used it.

## Acceptance gate

Automated regressions, synthetic fixtures and native playback cannot prove room echo cancellation. Complete at least 20 real voice turns across speakers/headphones and fan on/off, including silence during playback, natural interruption, follow-ups and complete final sentences. Record false activations, exact identifiers and stage timings. Targets are median ≤3.5 seconds, p95 ≤6 seconds warm finish-to-first-audible-answer, and interruption ≤0.5 seconds. Report misses and cold startup separately. Do not mark the acoustic repair complete before this human check passes.
